# 技术通用概念

  • namespace（命名空间）：用于限定名称有效范围的机制，允许不同范围内的名称重叠。

  • RPC（Remote Procedure Call，远程过程调用）：一种允许程序像调用本地函数一样调用远程服务的通信协议。具体表现为调用代码让另一台服务器计算机去算，算完把结果传回来

  • proxy 和 gateway：

    • Proxy = 代理：简单转发，只管 "把请求递过去"，像传话筒。
    • Gateway = 网关：统一入口 + 一堆管控能力，像前台 + 保安 + 调度 + 监控。

  • callback 机制：在 API 调用中，客户调起一个 Agent 任务后不等结果直接断开连接；客户提前留一个自己的网址（回调地址），等 Agent 把漫长任务跑完后，Agent 的服务器会主动给客户那个网址发一个数据包（JSON），把最终结果送过去。

  • SSML = 给 AI 语音的具体指导。它是一种基于 XML 的标准格式，通过简单的标签指令，告诉 AI 语音合成引擎（TTS）该怎么读文本，而不是默认机械地朗读。

  • Apache：

    1. Apache 服务器（最常见情况）

      它是一个运行在电脑（服务器）上的后台程序。它的核心工作只有两件：

      ** 接收请求：** 时刻盯着服务器的网络端口（80 和 443 端口），等待浏览器（如 Chrome）发来的访问请求。

      ** 返回内容：** 当你输入网址或点击链接，它收到请求后，会去服务器硬盘里找到对应的文件（比如 HTML 网页、图片），把这些文件的原始数据通过网线传回给你，让浏览器渲染成页面。

    如果请求的不是静态文件，而是需要计算的数据（比如登录验证），它会把这个请求转交给后端 PHP 或 Python 程序，等程序算出结果后，再取走结果返回给浏览器。它本身不处理业务逻辑，只负责收发数据和调度资源。

    1. Apache 基金会（开源组织） 它是一个美国的非营利组织，全称是 Apache 软件基金会（ASF）。这个组织不自己写代码卖钱，而是提供法律、资金和基础设施支持，帮很多开源项目团队托管代码、管理社区。我们常用的很多大数据工具（如 Hadoop、Kafka）都是这个基金会的项目，上面提到的 Apache 服务器也是其中之一

  • 幂等：对于同一个操作，你执行 1 次和执行 100 次，对系统产生的最终数据结果是完全一样的，数据不会被多次改变（重复扣款、重复下单、重复写入）。要实现幂等，核心做法是让每次请求携带唯一凭证（如订单号、请求 ID），服务端先据此判断该请求是否已经处理。

  • p99：99% 的请求都低于这个网络时延，剩下 1% 更慢。高并发系统里，1% 可能代表每分钟成千上万次失败体验。

  • TCC（分布式事务） 是一种保证方法：

    1. Try 阶段：先检查所有资源是否可用（比如检查账户余额够不够）。
    2. Confirm 阶段：确认所有检查都 OK，正式执行操作（正式扣款）。
    3. Cancel 阶段：如果任何一步出问题，回滚到之前的状态（退款）。

  • veFaaS：火山引擎版 FaaS（Function as a Service，函数即服务）。

# 业务通用概念

  • 灰度：小范围试点。

  • 开白：为客户开通特定产品、功能或服务的访问权限的简称。具体来说，就是让客户能够使用处于邀测、未公开或需要权限管控的相关服务。

  • badcase：badcase 是用来给产研团队改进方向的，无法指明迭代开发方向的低级错误不需要

  • 变更相关名词：

    1. 封网期：只能看，不能改动，防止关键时间点出问题。稳定能跑压倒一切。
    2. 窗口期：允许做系统变更的时间段，这时候员工 ready，有问题了可以及时处理。
    3. 熔断期：系统出问题后，自动进入的 "冷静期"。

  • SLA（Service Level Agreement） = 服务方的 "承诺 + 罚则"，用来保证你能享受到稳定靠谱的服务。

  • CAM 账户打通：把你在多个不同系统或网站上的账号，通过一个中心管理平台（CAM）关联并统一起来，做权限控制。"一个身份，全局通用"。

  • IAM（Identity and Access Management）：翻译为中文即直观易懂，通常在申请 "高权限账号" 时看到该词。

  • 信创 = 中国自己说了算的 IT 软硬件生态 ≈ 国产自研 + 国产可控 + 国产替代。（对应云上操作系统 tencentOS 的 "1 核心"，详见 "虚拟化・实例・专属部署" 文档）

  • GMV：广告推荐场景的商品交易总额。

# 附录・岗位术语

# 客户经理角色

  • TAM：技术客户经理。

  • CSM 部门（Customer Success Manager）：客户成功经理。

  • EPS 部门（Enterprise Partnership & Solutions）：企业合作与解决方案。

  • QBR：季度商业回顾，就是周会 PLUS 版，听众是客户。

  • NPS = "客户觉得你怎么样"（主观感受分）；P2S = "你干了多少活"（客观工作量分）。

  • 360 评估：全方位立体评价 —— 你身边所有人都来给你打分。

  • QPS 跳变：CSM 一般只关注跳变，以防高并发 query 打满服务器宕机。此外一个 query 可以包含多个问题，消耗的 token 也不同。

  • GOC（Global Operations Center，全球运行指挥中心）：稳定性保障核心团队。
