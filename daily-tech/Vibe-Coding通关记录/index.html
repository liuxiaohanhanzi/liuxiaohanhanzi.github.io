# Claude Code 代理

Claude Code 是基于 Node.js 运行的。Node.js 这个底层环境有一个众所周知的 “毛病”：它对 SOCKS5 代理的支持非常差劲。所以代理端口最好要支持 HTTP 协议。

按理说，我们在 cmd 中输入 claude 指令前，输入一行指令即可：

该指令告诉当前这个 CMD 窗口：“接下来，如果有任何程序想要发送 HTTPS 网络请求（比如去连 Poe 的服务器），请不要直接走大门（直连），而是把数据交给 127.0.0.1:7897 （代理软件）。”
Claude Code 底层是 Node.js 写的，Node.js 天生就认识并且会听从 HTTPS_PROXY 这个 “路牌” 的指挥。

# 补丁：IP 问题

# 问题背景

2026 年三月左右，GFW 技术升级，大量机场失效、跑路。博主所用的飞鸟、贝贝云、喵喵云均不再支持 clash

# 翻墙基础知识

可以把整套流程想象成 "寄快递"：

  • 协议 (Protocol) = 快递的打包和伪装方式 (怎么把货物包装得让人看不出是什么)
  • 客户端 (Client) = 你手上的快递操作软件 (帮你打包、选路线、发货的工具)
  • 服务器 (Server) = 国外的中转站 (帮你把货物真正送到目的地)

# 协议类 (Protocol）

技术协议 == 伪装流量的方法

  1. Shadowsocks (简称 SS)

最经典的一个。名字直译是 "影梭"。它的核心思路是把你的流量加密成看起来像随机数据，让审查系统难以识别这是 "翻墙流量"。它轻量、快、部署简单，是很多人入门的第一个协议。常见的 **"ss" 是 Shadowsocks 的缩写 **，两者是同一个东西。

  1. V2Ray (核心协议叫 VMess / VLESS)

可以理解为 Shadowsocks 的 "升级加强版平台"。它不是单一协议，而是一个协议框架 / 平台，支持多种传输方式和伪装手段 (比如伪装成正常的 HTTPS 网页流量)。功能比 SS 强大、灵活，但配置也更复杂。严格说 V2Ray 是一个内核 / 软件项目，里面包含 VMess、VLESS 等协议。

  1. Trojan

另一种思路。它不追求 "把流量变成随机乱码"，而是把流量伪装成完全正常的 HTTPS 网站访问。因为全世界每天有海量的正常 HTTPS 流量，把翻墙流量藏在里面就很难被单独挑出来封锁。核心理念是 "最好的隐藏就是看起来毫不可疑"。

  1. AnyTLS

这是较新的一个协议，同样是走 TLS (也就是 HTTPS 那套加密) 伪装路线，目标是解决前面一些协议被审查系统通过 "流量特征分析" 识别的问题，进一步提升伪装性和抗封锁能力。它属于这个领域比较前沿的方案。

这四个的关系: 它们是平行的、互相竞争的不同技术方案，就像 "顺丰 vs 京东 vs 邮政" 不同的打包送货规则。它们解决的是同一件事 (翻墙)，只是伪装和抗封锁的手段不同。

# 客户端类 (Client）

客户端 == 使用这些协议的软件。它是装在你手机 / 电脑上、有界面、帮你连接的 App。其强大之处在于：一个软件可以同时支持上面所有协议。

  1. Clash

最流行的开源客户端之一 (有 Windows、Mac、安卓、iOS 各种版本和分支)。它同时支持 Shadowsocks、V2Ray、Trojan 等几乎所有主流协议，并且有强大的分流规则功能 —— 比如让 "访问国内网站走直连，访问国外网站走代理"，自动切换，非常智能。免费、功能强，是目前很多人的主力工具。

  1. Surge

和 Clash 类似，也是一个功能非常强大的客户端，主要在 iOS 和 macOS (苹果生态) 上出名。它是付费商业软件，做工精细、功能专业，常被网络工程师和进阶用户当作调试网络的工具，不只是翻墙。可以理解为 "更专业、更高级、要花钱" 的 Clash 同类。

# GFW 打击现状

GFW 从 "被动封锁" 技术升级。不同协议因技术原理不同，抗封锁能力出现了明显分化。

  • 全加密流量检测：一段流量太像随机加密、不像任何正常协议，反而会被盯上，这正是裸 Shadowsocks / VMess 失效的根因。
  • 主动探测：如果服务器以确认自己是代理的方式回应（例如完成一次 Shadowsocks 握手)，该 IP 和端口会在数秒内被拉黑，封锁是持久的，且影响该服务器的所有用户。因此，单纯自建一台私人服务器并不再足以保护自己，曾经 "无法检测" 的 Trojan、VMess，因此被干掉
  • TLS-in-TLS 指纹识别：包括 Shadowsocks、VMess、VLESS、Trojan、obfs4 和 REALITY 在内的混淆代理流量，都可以通过检测被封装的 TLS 握手 (外层加密隧道内部出现的 TLS ClientHello) 被可靠地指纹识别，这种指纹是 "协议无关" 的 —— 任何封装了 TLS 应用流量的代理都会产生它。

目前各协议的大致 "生存状态"（2026 夏）：

  • ** 已经比较危险 / 容易被封的：**OpenVPN 或 WireGuard 基本已经被封；裸 Shadowsocks 也风险很高；Trojan 和 VMess 在经历了 2025 年的针对性打击后也大不如前。

  • ** 目前相对抗封锁的：** 业内公认现在最能打的是 VLESS + Reality。其原理很巧妙：服务端借用一个真实大站的证书来握手，当 GFW 的探测者连进来 (没有正确密钥) 时，服务端把这次连接透明转发到那个真站 —— 探测者看到的是一个货真价实的合法网站，分辨不出这是代理；此外 Hysteria 2 因为走 UDP、主打速度，在抗封锁上也常被推荐，但缺点是在部分地区 (尤其电信) UDP 会被限速。

  • ** 侧重性：**GFW 的阻断是概率性 + 有侧重的 —— 大流量节点更易被识别，小流量个人用户基本透明；而且你所在的省份与运营商在很大程度上决定了你能用哪些协议。河南就是个极端例子，当地部署了比国家级更激进的省级防火墙。

# IP 解决方案

  1. 在 duyao 测速网站，找到支持 clash、性价比高（月租 40 以下）的大机场，博主最后选择了 flowercloud

  2. 前往官网购买。注意：花云 flowercloud 注册时不一定需要填写手机号

  3. 导入 clash。注意：当前花云出于安全考量，不支持自动更新订阅更新。需要更新订阅配置，需登录网站前往 “复制订阅” 页面，点击按钮 “打开订阅更新开关”，在 10 分钟内完成订阅的更新操作

  4. 在 ipaddress 网站检查 IP 对应地址与 Fraud Score，选择美国与 Fraud Score 低的节点
